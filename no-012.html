## Git hygiene — always
1. Stage explicit paths only — `git add <specific files>`, NEVER
   `git add -A`, `git add .`, or `git commit -a`.
2. Check for a second session — if `git status` shows changes you didn't
   make, do NOT stage them. Unrecognized files are a stop sign.
3. Push after you commit — "committed" is not "backed up". Never end a
   session with silent unpushed commits.
4. Never commit secrets or junk — .gitignore first: .env, node_modules/,
   weights, build outputs. No remote at all? Flag it.
5. Write meaningful messages — one commit = one coherent change,
   never "wip".
6. Parallel work goes in worktrees — two sessions means two working
   trees, not a fight over one checkout.

Rule 1 · explicit paths add

Never add -A again.

A broad add doesn't know which changes are its own — it stages everything it finds, including another session's half-finished edits. The commit "works", the history looks clean, and someone else's broken change just shipped inside yours. Explicit paths make that impossible.

git add <file> · never -A · never commit -a
Rule 3 · push after commit push

Committed is not backed up.

Until it's pushed, a commit exists on exactly one machine — and local-only commits fail in silence. Nothing looks wrong until the laptop is gone. The rule: commit, then push, and if pushing isn't possible, say so out loud so a human can finish the job.

one machine ≠ a backup
Rule 6 · worktrees split

Two sessions. Two trees.

Rules 1–2 reduce the damage of a collision; worktrees remove the collision. git worktree (in Claude Code: claude --worktree <name>) gives every parallel session its own isolated folder and branch — instead of two agents fighting over one checkout.
