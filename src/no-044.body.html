Vercel or Netlify?
Static or edge?

Six words that get used as if they were interchangeable, and are not. Vercel is built around Next.js; Netlify is framework-agnostic with a build-plugin ecosystem. Static hosting serves every visitor the same pre-built file; edge functions run your code near the user and can answer each request differently. A preview deployment is a live URL for every branch; production is what your users actually hit. Below: what each pair really means, and what it costs you to pick wrong.

Fig. 01 ·

The three pairs.

Not “which is better” — each pair optimises for something different.

Vercel vs Netlify

Vercel is a deployment platform built and optimised around Next.js: first-class support for server components, edge functions, and incremental static regeneration.

Netlify is framework-agnostic — it works equally well across React, Vue, Svelte or plain static sites, with a strong ecosystem of build plugins.

Pick on what your app is, not on which brand you have heard more about.

Static hosting vs edge functions

Static hosting serves pre-built HTML, CSS and JS files from a CDN — the same content to every user, every time.

Edge functions run your code at data centres close to the user, letting you personalise, redirect, or fetch data on every request, without a full server round trip.

The question is only ever: does every visitor get the same thing?

Preview vs production deployment

A preview deployment spins up a live, shareable version of your app for every branch or pull request, so your team can review changes before they ship.

Production is the live version your actual users hit — pushed only after that review is done.

Temporary and disposable, versus the one that matters.

Fig. 02 ·

What it costs to pick wrong.

Each pair has a failure mode in both directions.

Platform

Vercel for a non-Next app means paying for integration you never use. Netlify for a Next app means re-implementing things the other platform gives you for free.

Static vs edge

Reaching for edge functions when the page is identical for everyone: you pay per invocation for output a CDN would have served free.

The opposite trap is worse — static-generating something that needs to differ per user, then patching it with client-side JavaScript that flashes the wrong content first.

Preview vs production

Reviewing changes on a local dev server instead of the preview URL. Local hides environment differences — env vars, build flags, edge behaviour — and those are exactly what breaks in production.

Fig. 03 ·

The one-line version.

Static when everyone gets the same thing. Edge when they don’t. Preview before production, always. And pick the platform your framework actually is.
