The agent that

An agent researches something brilliantly on Monday. On Tuesday you ask again and it starts from zero. That is not a memory problem you fix with a bigger context window — it is a process problem, and the fix is four files.

Fig. 01 ·

the loop, end to end

Every step writes to the state file. Every run reads it before doing anything else. That single relationship is the difference between a loop that compounds and four prompts in a trenchcoat.

Fig. 02 ·

why a bigger context window is not the fix

The obvious reading of "my agent forgets" is that it needs more room. It usually does not. Anthropic's own guidance on context engineering treats the context window as a budget to be curated rather than filled, and Claude Code's memory system is built the same way — instructions that must survive a session go in a file that gets re-read, not into an ever-longer conversation.[1][2]

So the question stops being "how do I make it remember more" and becomes "what should it write down, and what should it read before it starts". Those are process questions, and you answer them with files.

Fig. 03 ·

the four parts

01 · A weighted framework

Every candidate gets scored on the same factors, each factor multiplied by a weight you set. No exceptions, no "this one's obviously good". The whole value of a framework is that it gets applied identically to things you like and things you don't.

Show the working per candidate: factor, raw score, weight, contribution. If a raw score cannot be justified in one sentence, it is a guess, and it gets marked as one.

02 · An append-only state file

Every run records what it surfaced, what it scored, what you did, and what happened next. Every run after that reads the file before it does anything else. This is the part that makes it compound, and it is the one people skip.

It is also not a new idea. The decision journal — write down your reasoning at the moment you decide, then read it back when the outcome lands — comes out of Kahneman's work on calibration and was popularised by Farnam Street.[3] The reason it works is hindsight bias: once you know how something turned out, you sincerely misremember having expected it, an effect documented well enough to have its own review literature.[4] A file written before the outcome is the only honest record of what you actually thought.

## Run 2026-08-10
| candidate | factor        | raw | weight | contribution |
|-----------|---------------|-----|--------|--------------|
| ACME      | insider buys  |   8 |   0.25 |         2.00 |
| ACME      | fcf trend     |   4 |   0.30 |         1.20 |
Action: watchlist, no position.
Source: filings pulled 2026-08-10. Sentiment: unverified.

Append-only means never editing history. Corrections go in as new entries. That rule is what makes the file trustworthy six months later.

03 · A checker that argues back

A second pass over the shortlist whose job is to try to kill the first one. It looks for what the first pass did not examine, evidence that contradicts the reason something scored well, concentration risk, and anything the framework structurally cannot see.

The reason this is a separate pass and not an instruction is that a model asked to "be critical" while producing an answer will defend the answer it is producing. Give the critique its own run and its own input, and it has nothing to defend.

04 · A schedule

It runs Monday morning whether or not you remember it exists. A loop you have to remember to start is a loop that runs three times and then stops, and three runs is not enough state to be worth reading.

Fig. 04 ·

how I set it up

A skill file, plus a state.md that starts empty. Three tools attached: something that reads the open web, something that drives a real browser for anything the web reader cannot reach, and read/write access to wherever your notes live.

mkdir -p ~/.claude/skills/analyst && curl -o ~/.claude/skills/analyst/SKILL.md https://vektor-fm.github.io/vektor-site/files/analyst-skill/SKILL.md

The first instruction in the loop is read the state file end to end. Not skim, not summarise. A run that has not read the state file is a first run wearing a costume.

The second is that every figure gets its date and its source recorded at the moment it is written down. If a number cannot be sourced it goes in as unverified rather than being dropped — the gap is information. Six months later you will not remember which was which, and a number whose provenance you cannot reconstruct is not evidence.

Fig. 05 ·

where it breaks

The weights are the whole thing

The ones shipped in the file are placeholders. If you adopt someone else's weights without examining them you have learned nothing and the loop has nothing of yours to correct. Set your own, badly, and let the state file fix them.

The state file is a single point of failure

Everything else here is replaceable. Back it up.

One case is not a signal

Re-weight from outcomes, not from feelings, and not from a single ambiguous case. Two cases pointing the same way is a signal; one is an anecdote. This is the rule most likely to be broken in month one, because month one is when you most want the loop to have taught you something.

It is not financial advice

The worked example screens companies because that is a domain with a lot of public data and an obvious feedback signal. It is not a stock picker. The architecture is the point, and it transfers to suppliers, job candidates, papers, grants, or anything else you rank more than once.

Fig. 06 ·

does it earn a slot?

Yes, but not on week one. On week one it is slower than just asking. It starts paying somewhere around week four, when the file is long enough that the agent catches something it got wrong before you do.

If you only take one thing: point any recurring agent task at an append-only log and make reading it step zero. That works without the rest of this.
