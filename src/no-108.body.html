The LAYER page · commands, table, Mac notes

A 2.8T model, one layer at a time.

AirLLM "only ever keeps one layer on the GPU at a time, so the VRAM you need depends on the model's layer size, not its total size". That is how its README runs Kimi K3, 2.8 trillion parameters, in 3.72 GB of GPU memory. Here are the commands from the video, the README's memory table, the Mac notes, and the honest cost in speed and disk. Every line was read at its source on 2026-11-27: the README and the v3.1.0 release notes of github.com/lyogavin/airllm.

The commands.

The base install is one line. Kimi K3 needs a few extras on top, which its release notes call "none of them optional". All of it runs in a terminal and in Python.

1 · Install AirLLM

From the README's Quickstart:

pip install airllm

2 · Run a model

Pass a Hugging Face repo id (or a local path) and generate as with a normal transformers model. The README's example, trimmed to the two lines that matter:

from airllm import AutoModel
model = AutoModel.from_pretrained("Qwen/Qwen3-32B")

Swap in the repo id of the model you want; Kimi K3's is moonshotai/Kimi-K3 on Hugging Face. The README's full example, with the tokenizer and model.generate, is in its Quickstart.

3 · The Kimi K3 extras

From the v3.1.0 release notes, "Before you run K3":

pip install airllm compressed-tensors flash-attn

Plus two version rules, in the notes' words: "A CUDA 12 build of torch, because no prebuilt flash-attn wheel exists for CUDA 13 yet", and "transformers 4.56.x, as K3's remote code does not load on 5.x". Flash attention is mandatory: "K3's model code overwrites whatever attention implementation you request". So K3 needs an NVIDIA card with CUDA 12; it does not run on a Mac (Fig. 03).

4 · Disk first

The weights live on your disk and stream to the card. Kimi K3's checkpoint is 1.56 TB. For other models the README warns that "the original model will first be decomposed and saved layer-wise", so plan for room in the Hugging Face cache; setting delete_original to true keeps only the split copy "to save half of the disk space". For K3 the release notes say the split layers are hardlinked to the originals instead of copied, so it does not need the 3.12 TB a naive split would.

And Kimi K3

Not in the table but in the README's update line: Kimi K3 (2.8T) "runs on a single card in 3.72GB of VRAM, measured end to end on one RTX 6000 Ada". That card has 48 GB; the run used 3.72 GB of it at peak. It fits because K3 is a mixture of experts: the release notes say each layer holds 896 experts and each token is routed to 16 of them, and AirLLM loads just those.

The Mac notes.

From the README's MacOS section: "Just install airllm and run the code the same as on linux."

What a Mac needs

In the README's words: "make sure you installed mlx and torch"; "you probably need to install python native"; "only Apple silicon is supported".

github.com/ml-explore/mlx

Which models

"Only Llama-style models (LlamaForCausalLM, MistralForCausalLM) run on macOS for now; other architectures raise an error before anything is downloaded." Kimi K3 is not on that list, so on a Mac you run Llama- and Mistral-style models. The README's macOS notebook shows the setup, and notes that on macOS generate() takes the input ids positionally and returns the decoded text.

The catch: speed.

The README says it plainly: "every new token streams all layers from disk, so a reply can take a while". The v3.1.0 release notes measured how long, on one RTX 6000 Ada (48 GB) against the full 1.56 TB checkpoint.

The measurement

Peak VRAM during generation   3.72 GB
Peak VRAM after init          0.83 GB
Init (one-time per process)   900 s
Generation                    292 s/token, disk-bound

292 seconds is about five minutes a token, so a 100-token reply is about eight hours (our arithmetic). It is one machine and one run, self-reported; a faster disk would move it.

What it is for

Jobs you leave running, not chat. For the wait you get a frontier-size open model, private, on your own machine, with no API bill. Electricity and the disk are still yours to pay for.
