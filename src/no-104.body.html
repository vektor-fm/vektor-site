The SETUP page · two commands, then four agents

Install ECC, then start with four agents.

Everything Claude Code (ECC, github.com/affaan-m/ECC) is the open-source Claude Code setup by Affaan Mustafa; his README says he won the Anthropic x Forum Ventures hackathon in September 2025 building with it. It installs as one Claude Code plugin: agents, skills, commands and hooks. Here is what the video promised: the two install commands, and which agents to put to work first. Read from the repo's README on 2026-11-23 (ECC 2.2.3, MIT licence).

Open ECC on GitHubThe agents to start with

Fig. 01 ·

The two install commands.

Type them inside Claude Code, one after the other. Word for word from the README's "Claude Code details" section.

1 · Add the marketplace

/plugin marketplace add https://github.com/affaan-m/ECC

2 · Install the plugin

/plugin install ecc@ecc

This installs ECC's skills, agents, commands and plugin-managed hooks. Check what landed with /plugin list ecc@ecc.

What you need

Claude Code 2.1 or newer and Git on your PATH. It runs on Mac and Linux; native Windows is "supported with limitations" (the continuous-learning observer and memory-vault writes have open issues), and WSL follows the Linux path.

Install it once

Pick one install path per tool. The README is explicit: if you use these two commands, stop there and do not also run the full manual install, or skills, commands and hooks get duplicated. If a command reports an existing install or a scope conflict, the README points you to its guided setup instead of layering a second install on top.

Fig. 02 ·

The agents to start with.

The plugin brings every agent at once. The README's own advice is to start with the workflow you need, not the full catalogue, so these are the four to put to work first, each with the command from the README that calls it.

1 · planner, for any new feature

/ecc:plan "Add user authentication with OAuth"

The planner writes the implementation blueprint before any code. For a design call, bring the architect agent into the same plan.

2 · code-reviewer, after you write code

/code-review

A fresh-context review of what you just wrote, to catch regressions.

3 · build-error-resolver, when a build breaks

/build-fix

4 · security-reviewer, before you ship

/security-scan

An OWASP Top 10 audit of your code.

Then, for your stack

Add the reviewer for the language you write: /go-review runs go-reviewer, /python-review runs python-reviewer, and typescript-reviewer is called directly by name. The e2e-runner agent (Playwright end-to-end tests) comes in through the e2e-testing skill once you have user flows worth testing.

Fig. 03 ·

What the plugin leaves to you.

MCP configs: copy the ones you want

The plugin does not switch on ECC's MCP server definitions. The GitHub, Supabase, Vercel and Railway entries sit in mcp-configs/mcp-servers.json in the repo: copy the ones you use into your project's .mcp.json (or add them with /mcp) and replace the YOUR_*_HERE placeholders with your own keys.

Rules: add one pack, not all of them

Plugins cannot ship rules, so the README says to copy rules/common plus one pack for the language you actually use.

git clone https://github.com/affaan-m/ECC.git
cd ECC
mkdir -p ~/.claude/rules/ecc
cp -R rules/common ~/.claude/rules/ecc/
cp -R rules/typescript ~/.claude/rules/ecc/  # replace with your stack

Skills from your git history

/skill-create

Run it in a repo: it reads the git history locally and writes the patterns it finds as SKILL.md files. It is a command you run, not something that happens on its own.
