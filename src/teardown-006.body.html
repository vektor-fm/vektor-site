The hook that asks
before it greps.

A CLAUDE.md line asks Claude to check your repo map once. Graphify's hook asks again before every search, and in strict mode it refuses the first raw file read of a session. We fed the guard fake tool calls on 2026-10-19 and read what it printed: it blocks once per session, never twice, and not at all for a file you edited after the graph was built.

Fig. 01 ·

what the film said, and what is true

The Vektor film of 2026-10-09 said that after graphify claude install, Claude Code runs Graphify's guard before it greps or opens a file, and that with --strict a session's first raw read is blocked and sent to the graph.[1] Both statements hold. Neither has the conditions that decide whether you will ever see the block.

Graphify's README mentions strict mode once, in a section about a different editor, as "the GRAPHIFY_HOOK_STRICT=1 once-per-session indexed-read denial".[1] So the behaviour below is read from the installed program's source and then confirmed by running it, not taken from documentation.[2]

Fig. 02 ·

the decision chain

Claude Code runs a hook as a separate program before the tool call and reads its output. Two kinds of output matter. additionalContext is wrapped in a system reminder and placed in front of Claude; the tool still runs. A permissionDecision of deny stops the call and shows Claude the reason.[3] The guard uses the first for everything and the second exactly once.

The matcher in settings decides which tools reach the guard. "Bash|Grep" is an exact list of two tool names; "Read|Glob" likewise.[3] Inside the guard, the search side speaks only for the Grep tool and for Bash commands containing grep, ripgrep, rg , find , fd , ack  or ag . An ordinary shell command passes in silence.[2] Strict mode never blocks a search or a Glob; the source says a compound shell command has no single target to check and that blocking file listing would strand navigation.[2]

Fig. 03 ·

what we measured

Measured 2026-10-19, Graphify 0.9.46, using the render engine's graph. Session A, first Read of an indexed file: deny. Session A, second Read: nudge, so the read runs. A new session B, after a graphify query: nudge, no block. With GRAPHIFY_HOOK_STRICT=0 set: nudge. That is one block per session and zero after.[4]

We also hit the condition most people will hit first. Our first probe read a file the graph did not list and got the plain nudge, not a deny. The manifest check is real: a file outside the graph is never blocked.

Two further conditions come from the source and were not run separately: a file edited after the last graph build softens to a "graph may be stale" nudge and never blocks, and reads of non-source file types or paths outside the project are ignored.[2] In practice that means a heavily edited file will not be blocked until you run graphify update ..

Fig. 04 ·

what the detour is worth

On 2026-08-18 we ran one question about our render engine (196 files) two ways: about 2,000 tokens through graphify query, against about 27,184 tokens reading the six files involved. That is roughly 14 times fewer on that question.[4] The file-side figure is a bytes-divided-by-four estimate, and it is one question on one repository, not an average. The full graph file is about 403,000 tokens, larger than the roughly 371,000 tokens of code it maps, so the saving comes from bounded answers, never from reading the graph.[4]

What we have not measured: how often Claude actually follows the nudge when a grep is one keystroke away. There is no current number for that.

Fig. 05 ·

the file

Two parts. The settings fragment is what graphify claude install writes, with --strict added to the Read entry; the installer writes an absolute path to the graphify executable, so yours will differ. The script is ours and replays the three cases above on your own graph.

// .claude/settings.json
{
  "hooks": {
    "PreToolUse": [
      { "matcher": "Bash|Grep",
        "hooks": [{ "type": "command",
          "command": "graphify hook-guard search" }] },
      { "matcher": "Read|Glob",
        "hooks": [{ "type": "command",
          "command": "graphify hook-guard read --strict" }] }
    ]
  }
}
#!/usr/bin/env bash
# guard-check.sh <file-the-graph-indexes>
# Run from a repo that has graphify-out/. Prints what the strict guard does.
f="$1"
rm -f graphify-out/cache/last_query_stamp          # forget any recent orientation
verdict() {                                        # $1 = session id
  printf '{"tool_name":"Read","tool_input":{"file_path":"%s"},"session_id":"%s"}' "$f" "$1" |
    graphify hook-guard read --strict |
    grep -o 'permissionDecision":"deny\|additionalContext' | head -1
}
echo "session A, read 1: $(verdict a-$$)"           # expect permissionDecision":"deny
echo "session A, read 2: $(verdict a-$$)"           # expect additionalContext
graphify query "what does this repo do" >/dev/null 2>&1
echo "session B, after a query: $(verdict b-$$)"    # expect additionalContext

Install: uv tool install graphifyy (two y's); graphify update . in the repo (code only, AST, no API cost); graphify claude install; add --strict to the Read entry; then bash guard-check.sh <a file listed in graphify-out/manifest.json> and expect deny, nudge, nudge. The graph is a snapshot: rerun graphify update . after code changes, or graphify hook install to rebuild on commit.[5]
