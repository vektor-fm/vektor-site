Fig. 02 ·

Switch, then run it.

From Claude Code's model configuration docs (code.claude.com/docs/en/model-config, read 2026-11-15): /model <alias|name> switches immediately, in the same session.

1Open the project. cd into it and start claude. Commit or branch first, so every fix it makes is a diff you can read and undo.
2Switch to the new model. Type /model and pick it from the list. The conversation, the files and the skills stay where they are.
3Paste the prompt. Let it read the whole project. It fixes what it is sure about and hands you the rest as a list.
4Review the list, then the diff. Run your tests before and after. Keep what holds, revert what doesn't.
5Do it again at the next release. Same prompt, same project, new model: you see what it picks up that the last one missed.

Fig. 03 ·

What it found on our repo.

Our run, labelled as ours: the prompt above, word for word, on a throwaway copy of our own Instagram DM funnel (a Cloudflare Worker), Claude Fable 5.2 in Claude Code, 2026-11-16, 04:20 to 04:27 UTC. Nothing from this copy was deployed.

37Findings in all: 13 it fixed itself, 24 it listed for us to review. By kind: broken 12, inconsistent 15, inefficient 5, no longer needed 5.
1Broken. A dry run of our follow-up sweep deleted the queued record of anyone already nudged, although the code promises a dry run changes nothing. The delete now only happens on a live run.
2Inefficient. One history route listed up to 1,000 keys and read each one separately, up to 1,001 database queries. It now calls a one-query helper that was already in the code, unused.
3Inefficient. Keyword matching built a new regular expression for each of the 92 keywords on every comment. The patterns are now compiled once, in the same order.
4Tests before and after: the same results. The same test files passed and failed before and after its fixes. That is one run on one repo, not a benchmark.

Fig. 04 ·

Fable plans, Opus does the work.

Claude Fable 5.2 costs $8 / $40 per million input / output tokens, Claude Opus 5.5 $4 / $20 (Anthropic's pricing page, read 2026-11-15): twice the price per token. Anthropic's launch page also says Fable 5.2 at High effort scores about level with Opus 5.5 at Max for roughly half the cost per task, so "twice" is per token, not per job.

1The main session on Fable 5.2, as the orchestrator: it plans, splits the job and checks the results.
2Sub-agents on Opus 5.5. In a sub-agent's file under .claude/agents/, set model: opus in its front matter. The Agent tool also takes a model parameter, and CLAUDE_CODE_SUBAGENT_MODEL sets it for every sub-agent (model-config docs).
3What we can and can't promise. The split is the source creator's own setup for bigger projects. Nobody has measured the saving, so this page claims a cheaper per-token rate for the work, not a smaller bill.
