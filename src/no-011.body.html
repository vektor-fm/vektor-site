# CLAUDE.md — house rules for Claude Code
# Claude Code reads this at the start of every session. Put it in your project root.

## Operating rules — always
1. Smallest change that works. No refactors, no "while I'm here" edits.
2. Match the style of the file you're in. Read first, copy its patterns.
3. Done means the tests pass. Red isn't done — run the tests before you say done.
4. When unsure, ask — and never invent an API. Don't guess signatures.

## Operating rules — faster & cheaper
5. Plan first. List every file you'll change and wait for my go.
6. Search before read. Grep for the symbol; don't load whole files.
7. Show the diff first. Old lines out, new lines in — wait for a yes.

Rule 5 · plan first plan

List the files. Then go.

You hand Claude a task. Before it touches a thing, it lists every file it wants to change — and waits for your go. You approve a plan against a file list, not a surprise mid-edit. Fewer wrong turns, and a wrong turn is the expensive one: it costs the mistake, the correction, and the redo.

plan → approve → then it writes
Rule 6 · search before read search

Grep, don't swallow.

Instead of loading a whole file into context, Claude runs one quick search and gets back the exact lines it needs. On a real run that was 4 lines instead of a 2,251-line file — same answer, a fraction of the tokens. Context is the meter: every line Claude reads is a line you pay for.

4 lines · not 2,251
Rule 7 · show the diff first diff

See it before it saves.

Before writing anything, Claude prints the exact change — old lines out, new lines in — and waits for your yes. Nothing happens behind your back. You approve three lines you can see, not four hundred you can't. Faster to review, and safer to run.

3 lines you see > 400 you don't
