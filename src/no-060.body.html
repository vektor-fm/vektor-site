Claude Code · MarkItDown

The PDF goes in
as Markdown.

Hand Claude a PDF and Anthropic's docs say every page goes in twice: once as text, once as a picture of the page. Microsoft's MarkItDown turns it into Markdown first, so only the text goes in. Below: the install line and the command from the film, then Auto-Markdown for Claude Code, a hook that does the conversion for you every time Claude opens a PDF, and when not to use it.

The install line and the command.

What the DM promised. Needs Python. Tested with markitdown 0.1.8 on 1 October 2026.

1 · Install

pip install "markitdown[pdf]"

Double quotes work everywhere. MarkItDown's own README writes it with single quotes, which is a bash habit: Windows cmd and PowerShell pass single quotes through literally and the install breaks. uv tool install "markitdown[pdf]" or pipx install "markitdown[pdf]" keep it in its own environment. Check with markitdown --version.

2 · Convert

markitdown report.pdf -o report.md

The film types markitdown report.pdf > report.md, which is fine on macOS and Linux. On Windows use -o: our first run through a > redirect wrote the file in the console's cp1252 encoding instead of UTF-8. Then hand Claude report.md instead of the PDF.

Source: github.com/microsoft/markitdown (MIT licence, read 2026-10-01)

Fig. 02 ·

Why the PDF goes in twice.

What the docs actually say, read 1 October 2026.

Claude's PDF support

“The system converts each page of the document into an image. The text from each page is extracted and provided alongside each page's image.” Text costs “1,500–3,000 tokens per page depending on content density”, and each page image is billed on top of that, the same way as any image.

Docs: platform.claude.com/docs/en/build-with-claude/pdf-support (read 2026-10-01)

Claude Code's Read tool

“Claude reads short .pdf files whole. For PDFs longer than 10 pages, it reads in ranges with a pages parameter”, and “page-range reads render pages with pdftoppm”. A Markdown file is text only, so no page pictures are made for it.

Docs: code.claude.com/docs/en/tools-reference (read 2026-10-01)

Fig. 03 ·

Auto-Markdown for Claude Code.

A PreToolUse hook on Claude Code's Read tool. When Claude is about to read a .pdf, the hook runs MarkItDown on it, caches the .md, and points the read at the Markdown instead. Install once, never type the command again. Node built-ins only, no npm packages.

1 · Get the hook (one line)

curl -LO …/markitdown-claude-kit.zip && unzip …

Downloads the kit and puts the hook at ~/.claude/hooks/markitdown-pretooluse.mjs, so it works in every project. macOS, Linux, or Git Bash on Windows. Prefer clicking? Download the zip and copy that one file by hand.

~/.claude/settings.json 2 · copy this in

Wire it up

Merge this into the hooks block of ~/.claude/settings.json. If you already have hooks, add the entry to your existing PreToolUse array rather than overwriting the file.

settings.snippet.user.json
{
  "hooks": {
    "PreToolUse": [
      {
        "matcher": "Read",
        "hooks": [
          { "type": "command", "command": "node \"$HOME/.claude/hooks/markitdown-pretooluse.mjs\"" }
        ]
      }
    ]
  }
}

Keep $HOME, even on Windows: Claude Code runs hook commands through a POSIX-style shell, and %USERPROFILE% silently never ran in our test. For one project only, use settings.snippet.project.json from the zip with .claude/settings.json in the repo. A running session needs /hooks or a restart to pick it up.

3 · Check it worked

Ask Claude to read a PDF, then look in .claude/markitdown-cache/log.jsonl in your project: one line per decision, convert, cache-hit or fallback with the reason. Tested 1 October 2026 on Claude Code 2.1.285: 9 of 9 checks passed (conversion end to end, every fallback, both bypasses, the override, the cache).

Fig. 04 ·

When not to use it.

The page picture is how Claude sees a page. Converting throws it away, so this is a trade, not a free win.

1Charts and diagrams. If the figure is the content, Claude only gets the caption text after conversion. The hook guesses figure-heavy files (roughly 0.5 images per page and up) and leaves them as PDF, but it is a byte-scan heuristic: for anything you know is visual, name it something.images.pdf and it is never converted.
2Scanned PDFs. No text layer, and the base MarkItDown install does no OCR. The hook spots the near-empty result and hands Claude the original PDF instead.
3Tables. On our 48-page test file the cover page and several tables came out as broken pipe rows. Readable as text, not as a clean table. Check those.
4Turn it off. MARKITDOWN_SKIP=1 for the session; MARKITDOWN_FORCE=1 overrides the figure guess (never the scan guard). No MarkItDown on PATH means the hook steps aside and nothing breaks.
5Know what it approves. When it converts, the hook answers Claude Code's permission check with “allow” for the read of its own cached .md, so that one read does not prompt you. It only hooks the Read tool; a cat through Bash still sees the PDF.
