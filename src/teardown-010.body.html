The Teardown · 010

Does the Karpathy
file work?

A 2 KB CLAUDE.md with 235,000 stars on GitHub, tested the boring way: the same task, the same model, with and without it. It halved the code Claude added for one task, and it changed nothing about whether Claude tells the truth.

////////////////////////////////////////////////////////////////////////////////////////////////

Fig. 01 ·

what the file is

The repository multica-ai/andrej-karpathy-skills holds one file, CLAUDE.md, 2,357 bytes when we fetched it.[1] Its README says it is derived from Andrej Karpathy's observations about where language models go wrong when they write code, and it lists four principles: Think Before Coding, Simplicity First, Surgical Changes, Goal-Driven Execution.[2] The repository showed 235,182 stars on 2026-11-23.[1]

Claude Code reads a CLAUDE.md in your project root at the start of every session.[3] So the file is a standing instruction: no features beyond what was asked, no abstractions for single-use code, touch only what you must, state your assumptions. The question we wanted answered is the plain one: does a session that has this file write different code from a session that does not?

Fig. 02 ·

the same task, with and without

We copied a 15-line shopping-cart module and its one test into a fresh folder for every run. The prompt was the same every time: "Add discount code support to total(). The code SAVE10 takes 10% off." Model: Claude Sonnet, through claude -p in Claude Code 2.1.322. Four runs without the file, four with it. Run on 2026-11-11.

  • Without the file, 4 of 4 runs built a lookup table of discount codes to hold exactly one code, and one run's closing note says other codes "can be added to the DISCOUNT_CODES dict". Six lines added to cart.py every time.
  • With the file, 4 of 4 runs wrote one if for the one code. Three lines added every time. The tests Claude added were the same size in both arms (7 lines).
  • Assumptions: with the file, all 4 final messages flagged what Claude did with an unknown code and offered to change it. Without the file, 2 of 4 did.

Where the file did not help, or we saw no difference:

  • Claiming "done" without checking: not observed. Every one of the 14 runs in this test, both arms and all three tasks, ran the tests and reported the result truthfully. The file's "verify before done" idea changed nothing here because today's Claude already did it.
  • Touching code it should leave alone: not observed. The unused function in the module was left untouched in 14 of 14 runs, with the file and without.
  • "Add input validation": 12 and 18 lines added without the file, 10 and 10 with it. Two runs per arm, so we call that a lean, not a result.
  • "Make total() faster": one run per arm, identical one-line change.

Fig. 03 ·

the file and our test kit

We do not republish the file here: the repository carries no licence (the GitHub API reports none, 2026-11-23). Take it from the source:

curl -s https://raw.githubusercontent.com/multica-ai/andrej-karpathy-skills/main/CLAUDE.md

Our test kit is ours to share: the script that makes one run (run.sh), and the cart module and test it starts from (cart.py, test_cart.py). Save the file you downloaded as src/CLAUDE.md next to base/, then ./run.sh with 4 and ./run.sh without 4 run one task each, in a fresh folder, and leave the diff next to the transcript. It needs Claude Code installed and runs on your own usage; our 14 runs cost $0.66 in total (sum of each run's reported cost, 2026-11-23).

How we loaded the file matters, so we say it: in the "with" arm we passed it with --append-system-prompt-file rather than saving it as a project CLAUDE.md, because this machine's own global instructions would otherwise have leaked into both arms. In both arms we switched off every other instruction file and memory. That is a close stand-in for a project install, not the same thing.

Fig. 04 ·

install in 2 minutes
  1. Add it to your project. From the project root: curl -s https://raw.githubusercontent.com/multica-ai/andrej-karpathy-skills/main/CLAUDE.md >> CLAUDE.md. That creates CLAUDE.md if you have none and appends to it if you do.
  2. Begin a new Claude Code session in that folder. The file is read at the start of every session.
  3. Give it a small, vague task such as "add a discount code" and read the diff, not the summary. The thing to look for is structure nobody asked for.
  4. Keep it only if the diffs get smaller. The file adds about 2.3 KB to every session, so a project that does not need it should not carry it.

Time: not measured with a person.

Fig. 05 ·

what remains untested

One model, one 15-line repository, one main task run four times per arm. The discount result is the same in every run, which is why we report it, but it is one toy task: we do not know the size of the effect on a real codebase, on a longer task, or on a model other than Claude Sonnet. The file is also not free to carry: it is text that Claude reads before every task in the project.

We could not read Karpathy's original post ourselves: X returned HTTP 402 when we tried on 2026-11-23. What we say about it comes from the repository's README, which quotes it, so treat that as relayed.
