Fig. 01 ·

Two files, two loading rules.

CLAUDE.md and a skill both hold instructions. They reach Claude's context at different times.

CLAUDE.md loads whole, every session

“CLAUDE.md files are loaded into the context window at the start of every session, consuming tokens alongside your conversation.” A procedure written there costs context in every session, including the ones that never run it.

Docs: code.claude.com/docs/en/memory (read 2026-09-29)

A skill loads its name and description, then waits

At startup Claude Code puts a listing of skill names and descriptions into context. The SKILL.md body stays on disk until a request matches the description. Then it enters the conversation as a single message and stays there for later turns.

Docs: code.claude.com/docs/en/skills (read 2026-09-29)

Fig. 03 ·

What moves, what stays.

Anthropic's own sorting rule: “If an entry is a multi-step procedure or only matters for one part of the codebase, move it to a skill or a path-scoped rule instead.”

Stays in CLAUDE.md

Build commands, conventions, project layout, and “always do X” rules every session needs. Mine: never git add -A, stage explicit paths. That one stayed.

Moves to a skill

A multi-step procedure you run on one kind of day: a release checklist, a pre-delivery gate, a migration runbook. Reference material only one task needs.

If a skill never fires, check the description

Claude makes the match, so the description needs the words you'd type. Mine ends: “Use when asked to gate, QA, check, or vet a rendered vektor video”. Put the trigger words first: the listing cuts description and when_to_use at 1,536 characters.
