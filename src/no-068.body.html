Claude writes code for the library version it learned in training, not the one in your lockfile. Context7 looks the library up and puts its current docs into Claude's context first. Below: the two commands that add the Context7 plugin to Claude Code, the one sign-in step, and the CLAUDE.md rule that makes Claude use it without being asked.

Context7 plugin · Claude Code 1 · 2

Add the plugin

inside Claude Code
/plugin marketplace add upstash/context7
/plugin install context7@context7-marketplace

The plugin connects Claude Code to Context7's hosted server and adds two tools: resolve-library-id, which turns a library's name into a Context7 ID, and query-docs, which fetches that library's docs for your question. No local Node.js, npm or npx needed.

Fig. 02 ·

One sign-in.

Context7's docs: "No API key is required."

1Restart Claude Code. After the install finishes.
2Run /mcp. Select Context7 and follow the browser sign-in flow.
3Ask for it. End any prompt with use context7 and Claude looks the library up before it writes code.

Fig. 03 ·

Make it automatic.

Stop typing "use context7". Paste this line into your project's CLAUDE.md. It is the example rule from Context7's own README, which names CLAUDE.md as the place for it in Claude Code.

CLAUDE.md
Always use Context7 when I need library/API documentation, code generation, setup or configuration steps without me having to explicitly ask.

Source: upstash/context7 README, "Add a Rule", checked 2026-10-07.

Fig. 04 ·

The before and after from the film.

One fresh SvelteKit 3 project, whose package.json already declared the #lib alias. The same prompt, run twice on 2026-10-06 in headless Claude Code on Sonnet 5.5.

Without Context7

No docs lookup. Claude wrote the alias it learned in training:

import { greet } from '$lib/greet';

With Context7

The prompt ended in use context7. Claude called resolve-library-id, then query-docs for /sveltejs/kit, then wrote the files:

import { greet } from '#lib/greet.js';

Why it matters

SvelteKit 3.0.0 was released on 2026-10-01. Its migration guide: the $lib alias "is no longer generated automatically", it is replaced by a #lib alias declared in your package.json, and imports need the module extension. Sonnet 5.5's training data stops in June 2026.

One headless run per side, with Context7 attached for that session only. The plugin install, the sign-in and the CLAUDE.md rule above come from Context7's docs; they were not run for the film.

Know what you're adding.

Read this before you rely on it.

1Free has a limit. Context7's Free plan includes 1,000 API calls a month (context7.com/plans, checked 2026-10-07). Check the page before you rely on it; plans change.
2It helps where the library moved. If a library has not changed since the model's training data, Claude without Context7 may already be right. Context7 can only help for libraries it has docs for.
3Headless, SSH or CI machines. The plugin does not read CONTEXT7_API_KEY. Where a browser sign-in is not possible, Context7's docs point to npx ctx7 setup --claude or to adding the server by hand (all MCP clients).
