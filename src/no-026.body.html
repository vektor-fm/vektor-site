The turn · memory, not intelligence analyst

An agent that starts from zero every time isn’t a system.

Give an agent tools and a good prompt and it will research well — today, and then again from scratch tomorrow, having learned nothing. The fix isn’t a better model. It’s a state file: an append-only record of every run, what it surfaced, what it scored, what you actually did, and what happened after. Every run reads it first. That single file is the difference between a clever demo and something that gets sharper for as long as you keep it.

Fig. 02 ·

the four parts
01framework

A weighted framework.

Every candidate scored the same way, on the same factors, with the same weights — including the ones you already like. A framework you apply selectively is just a preference with extra steps.

02state

A state file. Append-only.

Never edit history; append corrections as new entries. A file you can rewrite is a file that will quietly agree with you — and then the loop is learning from a story instead of from what happened.

03checker

A checker that argues back.

A second pass whose job is to kill the first pass’s thesis, not confirm it: what it didn’t look at, what contradicts its own reasoning, what the framework structurally cannot see.

04schedule

A schedule, so it runs without you.

Weekly is enough. It pulls fresh data, scores, checks the state file for what moved, and drops a ranked shortlist with a one-page thesis. The thesis matters more than the ranking.

---
name: analyst
description: Run a repeatable, self-auditing research loop over a set of
  candidates - screen against a weighted framework, log every run to a
  state file, challenge the first pass with a checker, and re-weight from
  what actually happened.
---

# The Analyst

## Step 0 - read the state file FIRST
Before anything else, read state.md end to end. Pull out:
  - every candidate surfaced before, and what it scored
  - every weight adjustment made, and the run that caused it
  - anything on the Do-not-resurface list, and why
Never skip this because the file looks long. A run that has not read the
state file is a first run wearing a costume.

## Step 1 - gather
Note the DATE and SOURCE for every figure, at the moment you record it.
If a figure cannot be sourced, record it as `unverified` rather than
dropping it. The gap is information.

## Step 2 - score against the framework
Score each factor 0-10, multiply by weight, sum. No exceptions, no "this
one is obviously good". Show your working per candidate. If you cannot
justify a raw score in one sentence, it is a guess - mark it as one.

## Step 3 - the checker
A second, adversarial pass over the shortlist. Its job is to try to kill
the first pass. It looks for what the first pass did not examine, evidence
that CONTRADICTS the reason it scored well, concentration risk, and
anything the framework structurally cannot see.

## Step 4 - write the run to the state file
Append one row per run. Never edit history; append corrections as new
entries. The append-only rule is what makes the file trustworthy.

## Step 5 - re-weight from outcomes, not from feelings
When something plays out, ask which FACTOR was wrong, not whether you
were unlucky. Change that factor's weight and log the change with the run
that caused it. Do not re-weight from a single ambiguous case: two cases
pointing the same way is a signal, one is an anecdote.

Fig. 04 ·

the honest part
What this does not do honest

It is a research loop. It is not financial advice.

The reel uses stock screening as the worked example because it is a domain with a lot of public data and an obvious feedback signal — but the architecture is the point, and it transfers to suppliers, candidates, papers, or anything else you rank repeatedly. This produces a ranked shortlist and the reasoning behind it. It does not tell you what to do, and nothing in it is a recommendation to buy or sell anything. If you point it at markets: a scoring framework organises your judgement, it does not replace it, and past outcomes do not predict future ones. Figures it cannot source stay labelled unverified — a research system that hides its gaps is worse than none, because you will trust it.
