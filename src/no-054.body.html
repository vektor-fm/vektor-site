Fig. 02 ·

The fix isn't louder rules.

A rule buried in a long file doesn't reliably stop anything. Anthropic's own move was the opposite of writing more.

“We removed over 80% of Claude Code's system prompt”

Anthropic's Thariq Shihipar, 24 July 2026: “We removed over 80% of Claude Code's system prompt for models like Claude Opus 5 and Claude Fable 5 with no measurable loss on our coding evaluations.” The newer models don't need the hand-holding older rulebooks were written for.

Source: claude.dev blog, “The new rules of context engineering for Claude 5-generation models,” 24 July 2026.

Every rule is a speed bump before the task even starts

A long CLAUDE.md doesn't just risk being ignored under pressure, the way #15443 was. It's also something the agent has to read and weigh, every session, before it does anything useful. Fewer, sharper rules beat more of them.

Fig. 04 ·

What it actually flagged.

/doctor doesn't call a rule "outdated." It calls it derivable, something Claude could work out itself by reading the repo, or already covered somewhere that always loads. Three of the nine, quoted exactly, plus the two lines that were just wrong.

1. A description of two folders

- public/ — render assets. public/audio/<slug>/ VO + music, public/images/, etc. / Remotion staticFile() resolves against public/. Why it's safe to cut: Claude can open the folder and look. It doesn't need to be told what's in it.

5. A nine-line section describing internal code

A "Transitions" block spelling out an internal function's allowed values, when a separate automated check already enforces the same coupling, and the values are already listed one section below. Redundant with something that always runs.

9. "Write meaningful commit messages."

A generic practice the model already follows by default. Flagged in the shared, always-loaded rulebook, not the project-specific one, which is exactly the kind of block that's easy to miss by hand.

The two lines that were just wrong

/doctor also caught two stale instructions, a different and more important kind of finding than a redundant one. One told sessions to deploy a Cloudflare Worker with a raw command that can ship whatever code happens to be checked out, not what was reviewed. That one could have broken something live. Fixed to point at the safe wrapper script instead.

Fig. 05 ·

What stayed, on purpose.

Trimming isn't the same as gutting the file.

Every non-negotiable, gate and "never"

Anything that contradicts a tool's default behaviour, every documented failure mode with a specific fix, every hard gate, stayed untouched. The nine flagged blocks were the derivable and the redundant, not the load-bearing rules.

Auto memory now carries the rest

Claude Code's auto memory, on by default, now saves the preferences worth keeping on its own, so a standing rulebook doesn't have to hold them either. That's a big part of why the newer files can be this much shorter than the ones written a year ago.

Docs: code.claude.com/docs/en/memory

Claude Code

Type /doctor in a session inside your project. It reads every CLAUDE.md that loads for that session, explains its reasoning for each flagged block, and edits nothing until you say go. Needs Claude Code 2.1.206 or later.

The Codex version

There's no built-in equivalent yet, so ask for the same pass by hand:

codex-doctor-prompt.txt
Read every AGENTS.md file that loads for this session. For each rule in it, check
whether I could reasonably expect you to work it out yourself by reading the
code or repo, without being told. Flag any rule that is:
1. something you could already infer from the codebase,
2. redundant with another rule stated elsewhere that always loads,
3. describing a dead or legacy code path, or
4. factually stale (contradicted by what's actually in the repo).
For each one, quote the exact line and say why it's safe to cut. Leave every
non-negotiable rule, safety gate, and repo-specific gotcha alone, I only want
the derivable and the stale stuff flagged. Don't edit anything yet, just report.
