VISION.md
# VISION.md

Read this before any plan. It says what I am building, what good looks like to me, and which calls stay
mine. If a task is not covered here, ask me one question before planning; do not guess my taste.

## 1. What I am building

<One paragraph. The product, who it is for, and the one thing it must do well.>

## 2. What good looks like

<Five to seven rules you would use to reject a draft. Concrete enough to check.>
- Plain sentences. If I would not say it to a colleague, it is wrong.
- Every number carries its date and source, in the same line.
- One idea per screen. If a view needs a second idea, it is two views.

## 3. What I would kill on sight

<Three to five things that look fine to a model and wrong to me.>
- A feature added because it was easy, not because it was asked for.
- A "quick fix" that leaves the root cause in place.

## 4. The calls that stay mine

<Decisions Claude proposes and never makes.>
- Anything that changes what the product is for, or who it is for.
- Deleting or renaming public interfaces, routes, files other people depend on.
- Spending money, sending messages, posting, deploying.

For these: write the plan, name the options, say which one you would pick and why, then stop and wait.

## 5. How to work with me

- Start in plan mode for anything that touches more than one file. Propose, then wait.
- When the vision does not cover a case, ask one question. One, not five.
- Push back when I ask for something that breaks section 2 or 3. Say why in one line.

This is the short version. The kit's VISION.md has more worked examples per section. Keep yours short: Anthropic's docs target under 200 lines per CLAUDE.md file, and “imported files also load at launch”, so every line costs context in every session.

Fig. 02 ·

One line imports it every session.

Run from your project folder. Both lines append the import to an existing CLAUDE.md without touching what is already there. Tested 2 October 2026 on Claude Code 2.1.285, Windows 11, in both shells.

2 · macOS / Linux / Git Bash

printf '\n# Vision\n@VISION.md\n…' >> CLAUDE.md

2 · Windows PowerShell

Add-Content .\CLAUDE.md "`n# Vision`n@VISION.md…"

What both lines write, if you'd rather type it: a # Vision heading, the bare line @VISION.md, and one sentence telling Claude to stop at section 4. In our test Claude answered a question only VISION.md could answer in its first turn, with no file read, so the file was in context from launch.

Check it loaded

Run /context in an interactive session and look for VISION.md under Memory files. /context only works interactively; in a headless claude -p run, ask a question only VISION.md can answer instead.

Docs: “CLAUDE.md files can import additional files using @path/to/import syntax. Imported files are expanded and loaded into context at launch alongside the CLAUDE.md that references them.” code.claude.com/docs/en/memory (read 2026-10-01, re-read 2026-10-02)

Fig. 03 ·

Plan mode: Claude proposes, you decide.

The file says what good looks like. Plan mode is what makes Claude stop and show you the plan before it edits.

3 · Turn it on

Press Shift+Tab until the status bar reads ⏸ plan mode on. On a current install that is rarely one press: the cycle starts in auto mode. Or prefix one prompt with /plan, or start the session with:

claude --permission-mode plan

Make it the project default

{ "permissions": { "defaultMode": "plan" } }

In .claude/settings.json. Tested 2 October 2026, headless, in a throwaway folder: with the flag and with this setting alone, Claude was asked to create a file and never did; it returned a plan instead. VS Code sessions don't read this for the starting mode: set claudeCode.initialPermissionMode to plan in VS Code user settings.

When the plan is ready

Claude asks how to proceed: Yes, and use auto mode (or Yes, auto-accept edits where auto mode is unavailable), Yes, manually approve edits, or No, keep planning. Ctrl+G opens the plan in your editor so you can change it first.

Docs: code.claude.com/docs/en/permission-modes (read 2026-10-01, re-read 2026-10-02)

Fig. 04 ·

What it does not do.

Five things we found reading the docs and testing the kit. Know them before you trust the setup.

1It guides, it does not enforce. Docs: “Claude treats CLAUDE.md files as context, not enforced configuration.” The file is what the plan gets judged against; plan mode is the gate. To block an action whatever Claude decides, you need a hook.
2Don't paste the snippet file whole. The kit's CLAUDE.md.snippet.md wraps its example in a code fence so it reads well on GitHub, and “import parsing skips Markdown code spans and fenced code blocks”. Appending the whole file left @VISION.md inside the fence and it never loaded at launch. Use the one-liners above, or copy only the text between the fences. Same trap: a path in backticks is not imported.
3Claude Code now starts in auto mode. From 2.1.283, an interactive terminal session starts in auto mode, where a classifier reviews actions instead of asking you about each one. Without step 3, Claude edits and runs whatever the classifier allows.
4Bypass permissions beats plan mode. Docs: “Except in interactive terminal sessions with bypass permissions available, edits stay blocked until you approve the plan.” If you run with --dangerously-skip-permissions, plan mode is advice only.
5Relative paths. “Relative paths resolve relative to the file containing the import, not the working directory.” Keep VISION.md next to the CLAUDE.md that imports it.
