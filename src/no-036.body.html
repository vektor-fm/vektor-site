1. Every session starts from zero

If you think Claude Code actually knows your codebase, it is pretending. Each new session it rebuilds its mental model from scratch — the same greps, the same file reads, thousands of tokens spent remembering what it already knew yesterday.

Worth being precise, because the viral clips are not: Claude Code does not "re-read your entire codebase" every session. It uses on-demand agentic search — it reads what it needs, when it needs it. The true, checkable version of the complaint is that it re-greps and re-reads the same files across sessions, and pays for them again each time. That is the cost Graphify goes after.

2. What Graphify actually does

It scans your codebase once and builds a knowledge graph — functions, connections, structure — into one output folder (graphify-out/). Future sessions query that graph instead of re-reading your code. Free, open source, Apache-2.0, 107,661 stars read from the GitHub API on 18 August 2026, last push 17 August 2026.

3. Install

One line. Mind the double y — graphifyy is the real package name, and the single-y spelling is a different package. We ran this on 18 August 2026 and it worked first try.

terminal · install
uv tool install graphifyy

4. Build the graph

Run it from your repo root. It scans the codebase and writes the graph to graphify-out/graph.json. On our engine that took 196 files to a graph in one run.

terminal · first run
graphify update .

The graph is a snapshot, not a live index — after your code changes, run graphify update again or it answers from a stale map. That caveat is from the repo's own README.

5. Query it

Then you ask it questions instead of re-reading files. This is the actual question we asked about our own render engine — the one the receipts below are measured on:

terminal · query
graphify query "how does our caption system connect to the render pipeline?"

Swap the quoted question for your own. The answer comes back inside a bounded token budget rather than as a pile of file contents.

6. What the answer looked like

The question was "how does our caption system connect to the render pipeline?" and the route the graph returned is real: Captions() → Video.tsx → SceneBody() — Video.tsx is the composition root and SceneBody() is the scene renderer. Every edge on that route exists in graphify-out/graph.json; we verified the path by walking the graph ourselves on 18 August 2026.

Also worth knowing: our render script shares no AST edge with the source tree — it shells out to a CLI — so no path to it exists in the graph. A code graph maps code relationships; it does not see across a process boundary. Knowing what a tool cannot answer is part of knowing the tool.

7. What ≈14× is, and is not

It is one query, on one codebase, measured once. It is not a benchmark, and your number will differ with your repo and your question. We are printing it because it is the only Graphify speedup figure on this page that anyone actually measured and can check — and because fourteen times on a real codebase was enough for us to keep the tool installed.

8. "70× fewer tokens per search"

Both source reels carry this number. The repo's README never says it. Graphify's own blog is more honest than the clips quoting it: it calls the 71.5× figure "a community-reported number rather than a benchmark" — read at source on 18 August 2026. One user's anecdote, repeated until it sounded like a spec.

We replaced it with the ≈14× we measured ourselves. Smaller number, real provenance.

9. "Every new session Claude re-reads your entire codebase"

False as stated. Claude Code uses on-demand agentic search — it does not ingest your repo at session start (docs.anthropic.com, read 18 August 2026). The kernel that survives checking: it re-greps and re-reads the same files across sessions, and that repeated cost is real. The exaggeration was never needed to make the point.

10. The one we dropped entirely

One of the source reels claims Anthropic is upset about Graphify and that users are cancelling $250 plans over it. No source, no evidence, pure hype. It did not survive contact with a fact-check, so it appears nowhere in the film — and only here, as an example of what got cut.

11. The graph is bigger than your code

On our engine, the full graph.json weighs about 403k tokens against roughly 371k tokens for the codebase itself (both bytes÷4 estimates, measured 18 August 2026). So the win is per query — a bounded ~2k-token answer instead of a pile of file reads — never "the graph is smaller than your code". Anyone implying whole-graph savings has not looked at the file sizes.

12. It goes stale

The graph is a snapshot of your code at scan time. Change the code, and the map is wrong until you run graphify update again. Cheap to re-run, easy to forget — put it wherever you already put things you forget.
