# Draw your whole codebase as a galaxy

Measured 2026-09-24. One prompt in Claude Code (VS Code extension, Claude Opus
5.5, auto mode) shallow-cloned `microsoft/vscode` at commit `13de456`, read
`src/` only, and wrote back one file: `repo-map.html`, a self-contained,
offline, **1.34 MB** HTML page.

## What it drew

- **11 modules**, each a glowing cluster of stars.
- **10,022 files**, one star per file, sized by lines of code. The editor
  module alone holds 995 files.
- **2,836,738 non-blank lines** read to build the map.
- **107,661 file-to-file imports.** 61,998 of those cross a module boundary;
  collapsed to the module level, that's **32 module-to-module connection
  lines** flowing as animated particles between clusters.
- Hover a cluster to light up everything it touches. Click one to fly the
  camera in and see its individual files.
- Every file carries **one plain-English line** describing what it does,
  generated by reading that file. 1,435 of the 10,022 (14%) come from the
  authors' own code comments; the rest are generated from what the code
  itself declares (classes, registered commands, test suites), so some read
  a little mechanically.

**30 minutes wall clock. One prompt. Zero follow-up messages.**

A headless Chrome check on this laptop found 0 console errors and roughly
60fps steady, dipping to 50 to 57fps during the fly-in camera move into a
cluster.

## Prompt (a): the exact prompt that ran

This is word for word what produced the numbers above, VS Code URL included.

```
Clone https://github.com/microsoft/vscode (shallow, and only what you need). Turn this codebase into a living map in one self-contained HTML file, repo-map.html. Every top-level module of src/ is a glowing cluster of stars, one star per file, sized by lines of code. Imports between modules flow as animated particles along curved lines, so I can see what depends on what. The whole map slowly drifts like a galaxy. Hover a cluster to light up everything it touches. Click a cluster to fly into it and see its files, each with one plain-English line on what it does. Read the code to write those lines, don't guess. Keep every label readable, never overlapping. Dark, cinematic, smooth at 60fps, works offline, looks good on a phone screen in portrait.
```

## Prompt (b): the your-repo version

Same prompt, two swaps: the first sentence points at the folder you're
already in instead of cloning VS Code, and "module of src/" becomes "folder
of the source tree" so it fits any project layout. **Untested on other
repos.** The run above is the only one we've done.

```
Map the codebase in this folder. Turn this codebase into a living map in one self-contained HTML file, repo-map.html. Every top-level folder of the source tree is a glowing cluster of stars, one star per file, sized by lines of code. Imports between modules flow as animated particles along curved lines, so I can see what depends on what. The whole map slowly drifts like a galaxy. Hover a cluster to light up everything it touches. Click a cluster to fly into it and see its files, each with one plain-English line on what it does. Read the code to write those lines, don't guess. Keep every label readable, never overlapping. Dark, cinematic, smooth at 60fps, works offline, looks good on a phone screen in portrait.
```

Pointing it at someone else's repo instead of your own folder? Swap the
first sentence for: "Clone \<your repo URL\> (shallow, and only what you
need)."

## Before you run it

- **Where it runs.** Built and measured in Claude Code. The terminal, VS
  Code and JetBrains variants should read the prompt the same way since it's
  one plain message, no tool-specific syntax. It should also work in Codex,
  but that's untested; only Claude Code has actually run it.
- **Big repos take longer.** 30 minutes was for 10,022 files and 2.8 million
  lines. Expect less on a smaller repo, more on a bigger one, since the agent
  reads the real code to write each file's description rather than sampling
  filenames.
- **Don't add a second model pass for thin comments.** It sounds like a
  quality fix but it's a token-cost problem in disguise: a second full read
  of every file. The prompt as written already reads each file once and
  writes its line from what it finds, comments where they exist, the code's
  own structure where they don't.
