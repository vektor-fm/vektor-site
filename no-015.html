Write the
loop.

Boris Cherny, head of Claude Code, says the real skill now isn't a better prompt — it's loop engineering. Stop one-shot prompting. Write a loop that prompts the model, checks the result against a done-condition, and re-runs until it passes. Here's that loop — about 20 lines, runnable tonight — plus the one-page why. Free, no gate. As promised.

agent-loop.sh · plan → run → check → repeat
#!/usr/bin/env bash
set -euo pipefail

TASK="Fix the failing tests. Edit the source, not the tests."
CHECK="npm test"        # the DONE-CONDITION: exits 0 when the work is done
AI="claude -p"          # any CLI that edits your project from a prompt
MAX_ITERS=6             # a loop without a cap is a bill without a cap

last_output=""
for i in $(seq 1 "$MAX_ITERS"); do
  # PLAN + RUN — prompt with the task, plus last time's real failure output.
  prompt="$TASK

Done means this command exits 0:
    $CHECK"
  [ -n "$last_output" ] && prompt="$prompt

The check just failed. Find the cause, fix it, then stop:
$last_output"
  $AI "$prompt"

  # CHECK — the model doesn't decide it's done. This does.
  if last_output="$(eval "$CHECK" 2>&1)"; then
    echo "✓ done in $i iteration(s)."; exit 0
  fi
done
echo "✗ hit the cap — tighten your TASK or CHECK, not the count." >&2; exit 1

Piece 1 · the loop run

Plan. Run. Check. Repeat.

A one-shot prompt has no idea whether it succeeded — so the checking falls back on you, by hand, every time. The loop moves that into code: it prompts the model, lets it work one turn, then runs a real check and feeds any failure back in — until the check passes or it hits a cap. Two files, same 20 lines: agent-loop.sh for bash, agent-loop.py for Windows or no-bash. No framework.

Piece 2 · the done-condition check

The one line that matters.

The whole loop lives or dies on CHECK — any command that exits 0 only when the work is truly done: your tests, a build, a linter, a curl that must return 200. If you can't write it, you don't yet know what "done" means, and neither will the model. The model doesn't declare victory — the check does. And never let it edit its own check, or a stuck loop "wins" by deleting the test.
