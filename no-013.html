Agent.
Hired.

An AI agent is just an employee with one job. We ship a video every day with a team of them — a pitch agent, a build agent, a review judge — and the whole hiring paperwork is small markdown files. This is the starter kit: the agent template, the tools allowlist, and one complete skill you can run tonight. Free, no gate. As promised.

.claude/agents/review-judge.md · one employee, one file
---
name: review-judge
description: Strict read-only reviewer. Given a diff or feature,
  checks it against the project's rules and returns a GO / REVISE
  verdict with specific fixes. Use before merging or shipping.
tools: Read, Grep, Glob, Bash   # least privilege — no Write, no Edit
---

You are the review judge — a strict, consistent, read-only reviewer.

## The job
Your ONLY job: decide whether the change is safe to ship, and say
exactly what to fix if it isn't. You never fix anything yourself.

## Every run
1. Read the project's rules file — it overrides anything here.
2. Gather the real state: the diff, the changed files, the test run.
3. Check every rule. Resist leniency — reviewers drift toward
   "looks good"; default to flagging a real issue.

## What done looks like
VERDICT: GO | REVISE
— every finding as one line: what's wrong → the specific fix.

Piece 1 · the agent file hire

Who it is. One job.

The whole employee is one markdown file in .claude/agents/: a name, a description (the hiring ad — it's how Claude decides when to hand work over), a tools line, and the job contract — who it is, what it does every run, what done looks like. The template is fill-in-the-blanks with the guidance written inline, so the blanks teach you the pattern as you fill them.

Piece 2 · the tools keys

Least privilege.

The tools: line is the agent's keycard — and omitting it grants everything, including editing files. Same rule as a human hire: only what the job needs. Our review judge can't rewrite the code it grades, because we never handed it Write or Edit. The allowlist walks the three tiers — reader, reviewer, builder — with the safety logic for each.

tools: Read, Grep, Glob · start read-only, promote on need

Piece 3 · the skill sop

The daily review.

A skill is a written-down procedure any session runs the same way every time. This one is complete and runnable tonight: type /daily-review and it checks the working tree, unpushed commits, tests, leftover debris and today's commit messages — then returns a strict GO / FIX-FIRST verdict with specific actions. It's modeled on the judge that gates our videos every day.
